- 每台机器最多同时执行两个短连接管理请求，防止多个面板加载超过受控端八条连接上限；排队取消不执行请求。未修改受控端限制或放宽授权。
- 市场初次加载、手动刷新不再重复读取；读取失败清理旧安装状态并提示错误，不显示虚假的“不支持”。
- 安装准备阶段可中止私有工具下载；版本检查后再次检查取消状态，取消不切换已有客户端。
- 客户端版本按完整版本标记匹配，不使用子串匹配。失败不替换既有启动配置。
- 权限和启动配置先持久化再更新内存，存储失败不扩大有效权限。
- 新增权限 RPC 明确排除在通用 API/MCP 暴露面之外。

## Android SSH 机器工作区补齐

- 根因：Android 只在直接 Agent 连接中加载机器应用；SSH 分支一直只打开终端，没有桌面版的 cagent SSH bridge。
- SSH 认证完成后，通过独立 exec 通道检查当前用户已安装的 cagent；成功后显示机器桌面，保留终端和文件入口。未安装或桥接不可用仍保留 SSH，不自动安装、不改防火墙和权限。
- 浏览器使用同一条已核验 SSH 会话的 direct-tcpip 通道，域名在远端解析；断连关闭浏览器代理，不回退本机网络。浏览器资料按返回的 cagent 设备 ID 隔离。
- 编程应用和代码编辑器沿用 cagent 的安装状态；不把未安装客户端显示为可用。
- 美国机器的真实 cagent bridge `client.status` 调用成功。手机/平板尺寸夹具验证桌面入口、浏览器目标绑定、终端返回和断连清理；既有手机编程/编辑器 smoke 通过。
- Android Java 编译、lint、release 构建及既有签名证书校验通过。当前 adb 无已连接手机，尚未在用户手机上安装或完成真实 WebView 网络端到端验收。修复包保持 0.8.0，需手动覆盖安装，本轮未发布 GitHub 自动更新。

## 手机机器桌面与交互重整

- SSH/cagent 共用手机机器桌面：机器与连接标识、应用搜索、图标网格、最近打开、桌面底栏、四组背景与明暗主题。外观按连接保存在本机，不混入授权。

- 手机市场增加系统应用目录、安装计划和确认执行、任务进度；开发工具与安装任务分开呈现。未接入手机的原生图形安装入口不显示。完整能力包配置、WSL 管理及远端权限设置仍有差距，不宣称全端完全一致。
