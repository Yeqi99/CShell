# Windows 错误排查与验证（0.7.2）

日期：2026-10-21。范围为 Windows CShell、独立 CAgent 和本机实际 WSL；不代表所有平台、显卡或公网环境均已验收。

## 修复

- 远程桌面采集进程启动但未报告就绪时，以前可能无限停留在黑屏。现在启动阶段有进度超时与兼容采集回退，仍无画面时明确报告 `CAPTURE_NO_FRAMES`。
- 请求视频帧或关键帧时，原生管道错误现在进入会话失败处理，避免异步回调中的异常逃逸；旧采集实例不能影响新会话。
- HTTP 托管停止先关闭监听与现有连接，去重同一工作进程的终止操作，并限制系统终止辅助进程的等待时间。未能终止时保留错误，不能显示已成功停止。
- CAgent 终端退出原因现在贯穿服务端、传输通道和控制端，避免只显示无原因断开。

## 运行日志

CShell 设置 → 关于与更新 → 打开日志目录。默认路径为 `%APPDATA%\CShell\logs\runtime.jsonl`。

记录应用版本、时间、错误来源、消息和有限堆栈，包括后台 IPC 失败、界面异常、进程异常退出、终端退出与远控故障。不主动记录 IPC 参数、终端正文或请求内容；对常见密钥、认证信息、URL 路径和用户目录脱敏。分享前仍应检查内容。

日志按约 1 MiB 轮转，最多保留当前文件与 3 个历史文件，每分钟最多 120 条，不积压内存队列。磁盘不可写时不能影响原操作。此入口和记录器属于 CShell，不能替代远端 CAgent 自身的原生采集诊断。

旧 `activity.json` 只有操作结果与耗时，缺少错误原因；无法据此还原以前每一次 SSH 连接失败，也不能断言所有历史问题均已解决。

## 本机环境恢复

本轮发现 C 盘剩余空间为 0，独立执行 WSL 命令同样报 `Wsl/Service/CreateInstance/E_FAIL`。将约 9.5 GB 的项目测试产物迁至 D 盘后，Ubuntu 恢复启动，真实原生 PTY 验证通过。没有重装发行版或修改用户 Linux 数据。

本机 `test-results` 已映射至 `D:\CShell-build-temp\CShell-test-results-20261021`。迁移中未移动的残留保存在 `test-results-migration-remainder`，未删除。历史日志保留，不应提交这些本机产物。

## 验证

- 完整 Node 测试：347 通过，0 失败，0 跳过。包含 HTTP 托管停止与真实 WSL 原生终端验证。
- 远控专项 8 组、53 项通过：启动无进度、丢失帧确认、质量切换恢复、输入权限撤回、采集失败与重试等。
- 真实 Electron 日志冒烟通过：渲染错误、IPC 错误、脱敏和日志目录入口。
- SSH 文件面板关闭后重开、快捷键、目录和会话保留通过。
- 设置分类、跨分类草稿、保存/取消、暗色/窄窗口和底部操作区通过。

本机详细产物位于 `test-results/windows-error-full-tests.log`、`windows-diagnostics-smoke.json`、`windows-wsl-recovery-verified.json`、`windows-ssh-reopen.log` 和 `windows-settings-smoke.log`。本轮未向用户的远端服务器发送控制输入，也未验证真实公网长时间视频播放或所有显示器/锁屏组合。
