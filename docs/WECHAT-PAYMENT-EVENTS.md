# 微信转账与红包订阅事件

CShell 0.7.3 / 微信工具包 0.1.5 新增两种事件，适用于本机微信和已连接的 Windows CAgent。远端使用 CAgent 0.7.3 随附的微信运行包。

在智能体的事件订阅页选择本机微信或目标 CAgent，开启已有接收授权范围内的监听，再新建规则，选择「收到转账」或「收到红包」、处理会话和提示词。规则保存并启用后才会执行。智能体也可通过 `ai_event_sources`、`ai_event_save` 等既有规则工具管理这些事件。

| 类型 | 含义 |
| --- | --- |
| `message.received` | 原有普通消息事件，支付卡仍保留这一事件，不破坏既有规则 |
| `transfer.received` | 对方发来的有效转账通知，不包含收款回执或自己发出的转账 |
| `red_packet.received` | 对方发来的有效红包通知，不表示已打开或已领取 |

支付事件包含来源机器、账号、会话、发送者、消息 ID、时间、不可逆支付引用、通知类型和金额状态。转账金额来自卡片，单位为分；红包在通知阶段金额未知，`amountMinor` 和 `currency` 保持 `null`。`settlementStatus` 为 `unverified`，不能用于确认已到账。

红包身份使用独立微信工具包已验证的 sendid/channelid/msgtype 哈希映射，并校验原生 URL。原始 XML、支付票据和原生 URL 不进入支付事件或模型。收到通知的分类不调用收款、拆红包或发送消息；另一个会话中的按钮适配不因本次订阅功能而自动启用。

规则沿用接收范围、账号/机器绑定、冷却时间、每日调用与 token 预算、持久化去重及撤权检查。同一支付标识的重复通知不会重复触发同类型规则。监听仅覆盖开启后的新消息，不自动补跑历史款项；断线缺口仍明确报告。消息和支付类型是不同规则，若同时启用两类规则，两类均可触发。

## 验证范围

合成支付卡覆盖通知/回执、错误 XML、文本冒充、金额未知、标识缺失、敏感字段剔除、群/私聊身份及队列去重。本机与远端规则覆盖实际调度、停用、撤权、预算和游标保存；界面覆盖本机/远端事件选择和草稿保持。

2026-10-21：完整 Node 回归 350 项通过，Python 工具包 102 项通过；独立 React/Edge 订阅界面回归通过。安装后的本机 0.1.5 工具包也用合成转账卡核对了实际解析输出。

没有为本次验证领取真实转账或红包，也未启用用户规则。真实微信版本和原生模块仍按原工具包精确校验；不兼容版本不能假报监听成功。

## 0.7.4 本机原子工具接入

微信工具包 0.1.6 为本机 CShell 接入已单独安装的 `Weixin-4.1.15.50-tool`：`wechat_payment_parse` 解析单条 XML、`wechat_transfer_receive` 领取指定转账、`wechat_red_packet_receive` 领取指定红包、`wechat_payment_result` 查询指定操作结果。这些接口没有自动扫描、自动领取策略或回复发送者的业务逻辑。

领取必须分别启用「领取转账」「领取红包」及智能体的 `wechat.payments.receive` 权限，默认关闭；还需原会话历史读取授权。接口固定校验工具包文件摘要、微信绑定、原消息身份和提交前的权限及取消状态，共用原工具包的操作日志，结果未知时禁止盲目重试。当前领取仅支持 `wxid_` 联系人。

原子领取依赖本机独立工具包安装、共享日志和当前实例的原生验证记录；CShell 安装包不会复制这些记录。未安装、版本不符或验证缺失时明确失败。CAgent 不暴露这四个原子工具，也不会把安装微信能力包视为领取授权；远端仍支持上述通知订阅。验证仅使用合成输入和模拟调用，没有执行真实领取。

Python 回归 109 项通过，包括隔离进程提交前撤权；已安装的 0.1.6 包通过真实隔离解释器解析合成转账卡，金额为 10 分、到账状态保持未核验。事件模型请求去除每个工具重复的 JSON Schema 方言元数据，保留参数限制与原有预算，避免工具目录增长导致两轮事件任务提前耗尽预算。

最终 Node 全量 353 项中 352 项通过，1 项因并行构建期间 Windows ACL 子进程达到 15 秒超时而失败；该项原样单独复测通过，没有放宽 ACL 检查或超时。完整日志为 `test-results/payment-atomic-final-tests.log`，复测日志为 `test-results/payment-atomic-acl-recheck.log`。
