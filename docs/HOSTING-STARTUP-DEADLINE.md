# 托管代码启动与执行共用期限

此前五秒计时器在 spawn 返回后创建，较慢的同步进程启动会额外延长请求；即使启动已经耗尽五秒预算，仍会向子进程发送代码。独立测试以可控进程启动和单调时钟分别模拟四秒、六秒启动，两种情况在原逻辑下均失败。

现在在创建进程前记录单调时钟期限，启动后仅使用剩余时间。启动耗尽预算则终止自己的工作进程，不派发代码；预先取消的任务不创建进程。保留原五秒限制、进程终止等待、服务请求权限及九秒真实请求回归断言。该改动不保证 JavaScript 事件循环被阻塞时仍有操作系统级硬实时期限。

tests/hosting-startup-deadline.test.ts 覆盖剩余预算、过期不派发和预取消。tests/agent-hosting.test.ts 保留真实子进程超时、超额输出、取消和服务恢复。新增诊断记录响应、服务、终止耗时及事件循环延迟。

这修复了明确复现的预算遗漏；尚不能证明它是此前每次间歇性九秒超限的唯一原因。须完成修复后的两版全量回归与各平台构建后发布，不能用之前的全量通过替代。
