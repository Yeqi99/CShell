# CAgent 后台结束后的窗口退出恢复

## 实际复现

本机从 0.8.11 升级到 0.8.12 时，旧原生窗口保持曾经连接成功的状态，但其 app-host 已结束，控制 API 返回本机 Agent 未运行。关闭按钮按设计隐藏到托盘；菜单“退出 CAgent”仍向失效 app-host 发送更新状态和关机请求，随后显示“退出失败，请重试”，旧窗口继续持有单实例锁，阻挡新版窗口启动。

## 修复边界

原生窗口检查自己持有的 Process 对象：确认其已退出时，关闭窗口并清理托盘，不再请求失效后台，不自动安装无法重新核验的更新。关机请求发生竞态失败后也再次检查同一 Process 对象。后台仍存活、没有进程对象或进程状态不可确认时，不把请求失败当作退出成功，保留错误。没有新增强制结束进程、重放请求或授权操作。

## 验证

`scripts/agent-native-exit-smoke.ps1` 编译真实 CagentWindow.cs 与隔离 WPF 测试入口。测试持有一个真实已结束子进程，模拟窗口之前连接成功；旧实现明确失败“Dead host prevents native window exit”，修复后成功。另一分支持有活进程并让 API 请求失败，确认窗口仍报告退出失败。开源与 Pro 各自编译并通过；Windows CI 与 CAgent Windows 包流程已接入。

测试不触碰用户数据、账号或正在运行的 CAgent。当前本机仍为正式 0.8.12，未替换为开发构建。此提交晚于 0.8.13 冻结源码（Core e8563ce / Pro ca0daa8），不在现有 0.8.13 候选包中；随后续完成验收的版本交付，不为单个修复单独递增版本。
