## 后续实现进展（同日，优先于上文初始状态）

已验证 SNS 队列：`get_coro -> get_svc -> get_sns(0x1087ac0)`，服务 `+0x428` 包装对象解引用后调用 `0x57088f0`，只读通知查询限制 1 条以唤醒所属数据库线程。任务 `0x570fb90 -> 0x2802ca0`。固定自有查询在该线程读取 `sns.db`。已实际读取 13 张表结构，与时间线字段一致。

当前正文实际根节点是 `SnsDataItem`，内含 `TimelineObject` 和 `LocalExtraInfo`；适配器支持该包装及直接 TimelineObject。每页最多 5 条、每条 XML 最多 8192 字节；超限返回明确状态，不伪造空正文。拒绝 DTD/实体声明，限制 XML 深度/节点数。媒体只给元数据，不导出访问凭据或主动下载。

本地观测缓存最多 1000 条，按账号范围和帖子 ID 隔离，用整个源 XML 摘要检测旧帖变化；重复页不报新增，重启保留去重。未读取到的帖子不推断删除，缓存淘汰后再次观测可能重新报告。它不是服务端增量同步，也不是已验证的时间排序；当前沿用 SQLite signed tid 降序分页。

51 项 Python 测试和 9 项相关后端测试通过；独立 Electron 夹具验证权限链接定位、默认关闭与草稿保持。服务端刷新、发布均未实现，未提交任何朋友圈。

- 包含 `/cgi-bin/micromsg-bin/mmsnssync`、`mmsnstimeline`、`mmsnsuserpage`、`mmsnsobjectdetail`、`mmsnspost` 字符串以及 `micromsg.SnsPostRequest/Response` 类型名。字符串存在不等于获得可调用接口，也不能直接拼 HTTP 请求替代客户端认证与协议。

## 建议实现顺序

### 读取与增量

先接入本地缓存分页读取：帖子 ID 用字符串，返回来源、缓存覆盖范围和新鲜度；正文、媒体元数据、互动通知分别建模。XML 禁止外部实体并限制大小和深度。损坏记录明确报解析状态，不伪造空内容成功。

需要确定 SNS 数据库所属执行队列和一个确实只读的主动唤醒入口。沿用当前工具包的线程内固定查询与有界读取；不能从任意线程直接查询微信的 NOMUTEX 句柄，不能沿用旧进程的数据库地址。

随后验证服务端刷新与个人页分页，不要求用户先打开朋友圈。缓存按账号与帖子 ID 隔离；正文或互动变化产生更新事件。增量去重不能仅按发布时间，因为旧帖子仍可能新增评论或被删除。本地没缓存到的内容不可宣称不存在；页面查询不能宣称是完整历史。

### 发布

先验证纯文字，再做图片上传和发布关联，视频另验。必须解析发布数据模型、可见范围、任务生命周期、服务器返回的帖子 ID 与错误码。媒体上传成功不等于发布成功；函数返回也不等于服务端接受。

操作拆为准备草稿、提交、查询结果；绑定登录账号、内容摘要和可见范围。超时后先查任务结果，禁止盲目重发造成重复朋友圈。仅在参数和回执已确认后进行经用户明确授权的具体测试发布。

读取、刷新、发布分别授权，默认关闭，不继承聊天发送的 `*`。准备接口本身不发布。未实测能力不显示为可用工具。
