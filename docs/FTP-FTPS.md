# FTP 与 FTPS 文件连接

在新建连接中选择 FTP 或 FTPS，填写地址、端口、用户名和密码即可进入文件工作区。两者均独立于 SSH，不创建终端，也不提供浏览器、桌面或机器监控。密码使用现有加密凭据存储，不包含在连接分享内容中。

FTP 以明文传输账号、密码和文件，仅适用于用户接受此风险的网络。FTPS 使用显式 TLS（通常为 21 端口），校验服务器证书和主机名，同时保护控制与文件数据通道；验证失败不会降级到 FTP。当前不支持隐式 FTPS（通常为 990 端口）。

## 文件操作

- 浏览目录，单次最多 10000 项、2 MiB 原始目录列表；服务器未提供修改时间时显示为未知。
- 单文件上传、下载并显示进度；不覆盖已有文件。上传先写入专用临时文件，完成后改名；下载先写入本机临时文件，完成后以不覆盖方式保存。
- 创建目录、重命名、删除普通文件或空目录；不递归删除目录，不自动修改符号链接。
- 取消正在传输的任务会关闭实际连接和传输通道，之后需重新连接。排队任务不会自动重新连接。

FTP 协议没有可移植的排他发布操作。上传和重命名会在执行前检查目标，但不能保证与其他客户端写入原子互斥。断线、取消或响应丢失后，可能已完成远端变更；先检查目标，再决定是否重试。客户端不会自动重放变更。

## API、MCP 与智能体

FTP/FTPS 注册独立的 `cshell.ftp` Provider。工具通过统一授权入口运行，按真实保存连接身份和客户端所属会话约束。

| 权限 | 工具 | 用途 |
| --- | --- | --- |
| `files.read` | `list_files`、`ftp_read_text` | 目录、最多 64 KiB 的普通 UTF-8 文本 |
| `files.create` | `ftp_create_text` | 创建最多 256 KiB 的新文本文件 |
| `directories.create` | `ftp_create_directory` | 创建单个目录 |
| `files.rename` | `ftp_rename` | 普通文件改名，不覆盖 |
| `files.delete` | `ftp_delete_file` | 删除普通文件 |
| `directories.manage` | `ftp_delete_empty_directory` | 删除空目录 |

先通过 `describe_connection` 或 `discover_capabilities` 查询当前授权的工具契约，再调用 `invoke_connection`。未授权工具不出现在连接发现结果中；变更工具要求 `acceptNonAtomic: true` 并遵守已有审核策略。只授权文件的客户端无法得到终端、浏览器或桌面能力。账号、连接或权限变化会使旧授权失效。

## 验证

真实本机 FTP/FTPS 控制与数据通道 fixture 覆盖传输进度、证书及主机名验证、数据通道 TLS、跨主机被动地址拒绝、取消关闭通道、不覆盖、空目录删除、响应丢失不重放。真实 HTTP REST 与 MCP 协议覆盖工具发现、无授权拒绝、仅文件能力、客户端会话隔离和保存连接身份变更。生产服务器兼容性与各平台实机结果随发行记录说明。
