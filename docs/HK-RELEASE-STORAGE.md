# 香港发行存储检查与保留规则

每次发布前、静态附件部署后和清理后检查：

- `df -B1 /` 与 inode 使用率；剩余空间至少为 **5 GiB + 本次新增附件及回滚备份所需空间**。低于此值停止新包上传；低于 10 GiB 或使用率超过 90% 时先预警并准备清理。
- 检查最近 24 小时内核 I/O 错误、文件系统错误、只读重挂载和控制器重置；只输出计数，不复制其它服务日志。
- 确认存储设备类型及 SMART 是否可读。QEMU 虚拟盘无物理 SMART 时明确记为无法验证硬件寿命，不能把零日志错误称为物理硬盘健康证明。

发布成功且官网/更新清单通过后，开源与 Pro 各保留最近两版香港安装包。删除旧版本前逐文件核对历史 GitHub Release 附件存在且名称、大小匹配。缺失或不匹配先保留调查，不按版本数字盲删。

清理限定 `/opt/cshell-downloads/{opensource,pro}/v*` 的明确版本清单，以及已明确失效的 `/opt/cshell-release-staging` 候选目录。验证真实路径与父目录、拒绝符号链接；保留当前正式版本、上一版、当前候选收据和官网回滚备份。不触数据库、身份、微信、CanpAI 或其他服务。逻辑文件大小不等于实际释放空间（硬链接/共享备份可能仍持有数据），清理后必须再次读取 df。
