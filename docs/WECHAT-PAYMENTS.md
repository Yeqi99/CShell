# 微信支付消息识别

历史读取新增 contentStatus=payment-card。text 为 JSON，包含转账类型、CNY 十进制金额与整数分、原生 paysubtype。金额来自消息字段，不代表当前到账状态。未知金额格式返回 null，不猜测币种或金额；不输出 transferid、transcationid、支付备注或支付票据。

### 原生结果布局核对准备

继续静态分析确认：0x538d560 的操作分支 2 为 0x538da1c；该分支通过 0x2300ca0 读取对象 +0x210 字符串，调用当前账号 getter，并读取对象 +0x158 的整数时间字段。0x14bd0e0 为 +0x1f0 字符串 getter。叶函数可能不出现在 .pdata 中，不能用前一个 .pdata 记录当作其函数范围。

0x5392cc0 输出为两指针共享对象；对象地址为分配块 +0x10。静态看到 transport 状态位于对象 +0x28，retcode 字符串位于对象 +0x50，retmsg 位于 +0x30。这些偏移尚需用户手动收款的动态核对。函数中的 retcode 缺省值是字符串 0，故不能凭 0 单独推断到账；需要完整响应与关联回执。

新增 maintenance/observe_transfer_result.py/.c，被动观察入口与返回，不调用收款函数、不改原生对象、不落盘支付标识。保留在途调用直至返回后再卸载，输出字段长度、时间字段、传输码和数字返回码；始终 settlementConfirmed=false。真实进程一秒空闲加载测试通过，codeRestored/unloaded 为 true、retained 为 false；没有收款动作，也尚未动态验证结果字段。下一步需要用户手动领取一笔测试转账的完整观察。
