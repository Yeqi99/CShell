# OpenCode：账号、模型与官方运行时

## 在哪里选择模型

1. 在扩展市场启用 OpenCode，在扩展页保存 Key 或完成浏览器登录。
2. 打开智能体输入区的「AI 基座与模型」，进入 **OpenCode**。账号下会列出当前目录中的 Go / Zen 模型，支持搜索与刷新。
3. 直接选择需要的模型。无需逐个点「接入此账号」或为每个模型手动建立基座。正在执行的会话仍使用原模型；选择其他模型会创建对应的新会话。

打开模型菜单、应用回到前台时都会刷新。临时断网显示目录状态未知，不删除账号或把旧引用误判为永久下架。云恢复后在本机重新核验；本机可用状态不作为云端权限写回。

官方运行时使用的协议元数据也通过同一个已配置网络出口刷新，缓存最多 5 分钟，避免新模型被旧运行时内置目录误判为下架。元数据请求失败时保留内置目录；不能识别实际协议的模型会说明原因，不猜测请求格式。

基座卡片和编辑页显示实际目录状态。已有账号的「验证」不会修改默认模型；扩展页明确选择模型并点「接入此账号」才更新该账号默认值。付费模型不会因排序、故障或重试被自动选中。

## 桌面端如何运行

桌面端通过真实的官方 OpenCode v1 系列固定版本 **1.19.4** `serve` 运行时与其公开会话 API 调用模型。扩展页显示实际运行链；未提供运行时的宿主不能声称已接入官方客户端。Android 不启动桌面可执行文件。

首次实际发送或点「检测所选模型」时，按操作系统和架构准备私有运行时。支持的分发组合是 Windows x64、macOS x64 / arm64、Linux x64 / arm64；代码包含各自官方 npm 归档地址和固定 SHA-512。归档和唯一普通可执行文件经过校验，不运行 npm 安装脚本，不改全局 PATH，不安装系统依赖，不从归档解出任意路径或链接。保留官方 MIT 许可说明，运行时程序与许可放在同一目录。可执行文件保存在 CShell 自己的数据目录 `extensions/opencode/official-runtime/1.19.4/`。

Windows x64 已做真实运行时集成验证；macOS、Linux 的包源和摘要已核对，尚无本轮对应实机运行结论。首次下载较大，下载失败或宿主不支持时会保留账号并报告原因；不会偷偷回退另一客户端或模型。

每次请求使用独立工作目录、HOME、XDG 配置/缓存目录及内存数据库。官方服务只监听随机 loopback 端口并使用随机认证口令，不启用发现、不对外开放。禁用自动更新、外部插件、MCP、用户项目配置、外部 skills、LSP 下载和本机工具。进程隔离不是操作系统权限沙箱；官方二进制仍以当前用户运行。

运行时不接收真实 Key：Key 仅在 CShell 后端的有界网络桥注入。模型请求复用「设置 → 网络代理」中的实际出口；桥只接受固定 OpenCode 推理路径和当前模型，不接受任意代理 URL。设置的机器出口失效时请求失败，不回退本机直连。每个模型调用最多转发一次请求，取消或结果不明不重放。协议元数据从 models.dev 经同一网络出口按需读取并短时缓存，不额外调用模型；临时读取失败保留运行时已知协议，未知新协议明确提示待核验，不冒充服务端模型下架。

## 工具和截图

官方客户端只允许 `StructuredOutput` 输出回复与工具意图，不能自行访问文件、执行命令、浏览网页或启动子智能体。CShell 收到的工具意图仍通过原来的 Schema 校验、目标身份、机器范围、能力授权和审核执行。新工具不会因为换了模型而自动授权。

已授权的截图作为有界图像附件发送，不塞进普通文本工具记录。明确不支持图像的模型会给出提示；未知能力不通过额外推理探测认证，也不自动换模型。可使用网页 DOM 读取作为文字替代。

停止会话会取消模型等待并清理该请求的官方进程和临时目录；其他会话与原有官方 OpenCode 安装不受影响。CShell 会话仍在自身的加密存储中保存。

## 为什么认证成功仍可能不能生成

Key 验证、模型目录、实际推理是不同状态。目录包含一个模型，并不证明当前账号、套餐、地区或客户端政策允许调用。服务端拒绝时保留原账号、密钥、模型引用与会话；只更新该模型的可用状态，不改其他账号。

**2026-10-25 的真实验证：**现有账号通过官方 1.19.4 进程调用 `beam-free`（Go）、`mimo-v2.6-flash-free`（Zen）、`big-pickle`（Zen）均收到 HTTP 403。另用未经过 CShell 模型桥的原生 `opencode run --pure --format json -m opencode/big-pickle`，同样收到免费层客户端范围拒绝。没有取得这些模型的成功回复，不能写成“所有免费模型已可用”。测试没有调用付费模型、改 Key 或伪造客户端身份。上游 [issue #56324](https://github.com/anomalyco/opencode/issues/56324) 也记录了官方客户端内的同类拒绝；其维护说明认为可能涉及网关对网络或地区的判断。这是排查线索，不代表已经确定本账号的具体拒绝原因。

地区、额度与客户端范围拒绝会在基座状态中说明。调整套餐或合规网络出口后，可明确重新检测所选模型；成功后状态恢复。不会为了恢复状态发送后台付费探测，也不通过伪造身份绕过政策。

## 验证与维护

- `tests/opencode-official.test.ts`：归档摘要/文件类型、官方拒绝状态、显式恢复、保留账号及默认值、不回退旧 HTTP 推理、检测必须明确选择模型、Google 路径绑定模型、共享下载等待者独立取消。
- `scripts/opencode-official-smoke.ts`：需要真正官方归档；验证私有安装、实际官方本地 API、唯一结构化工具、工具意图交回、取消/清理、拒绝不重放。测试模型服务器是受控 fixture，不能冒充真实在线模型回复。
- `scripts/opencode-model-menu-smoke.ts`：真实浏览器中的动态二级菜单、前台刷新、断网恢复、运行中会话固定及窄面板布局。
- 官方契约：[Server](https://opencode.ai/docs/server/)、[Config](https://opencode.ai/docs/config/)、[CLI](https://opencode.ai/docs/cli/)。固定运行时版本需随契约和各平台摘要一起升级。

问题反馈只需提供版本、模型 ID、错误代码、时间和网络出口类型，不包含 Key、Authorization、Cookie 或完整连接凭据。
