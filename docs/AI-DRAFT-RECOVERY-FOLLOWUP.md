# 草稿保存状态恢复

0.8.11 后续独立修复，未发布。原来的 React hook 一次保存失败后只设置错误，不会在后续成功时解除；因此草稿已经保存，界面仍警告不要关闭窗口。

现在按会话和保存序号跟踪结果：同一会话最新保存成功后清除对应警告；其他会话成功不能掩盖未保存的草稿，旧请求晚到也不能覆盖新结果。初始恢复失败仍保留独立警告，输入文本和实际加密持久化方式不变。

验证使用真实 React hook、独立浏览器和可控制完成顺序的 IPC 替身，不访问用户账号或真实草稿：

- 旧版 hook 在“失败后成功保存应清除警告”断言超时，复现原问题。
- 新版覆盖恢复期间输入优先、跨会话错误隔离、恢复成功、乱序成功／失败、清空草稿、初始恢复失败不能被保存成功掩盖，完整通过。
- 现有两项加密草稿保存／损坏文件保留测试通过；Core TypeScript 检查通过。
- 首次新测试因 output 元素隐式 status 角色导致选择器歧义失败，修正为具体警告元素后重跑通过，未放宽业务断言。

回归加入 Windows release workflow。该浏览器验证覆盖 hook 状态，不等同成品 Electron 账号切换或磁盘故障实机测试；Pro 同步验证另行记录。
