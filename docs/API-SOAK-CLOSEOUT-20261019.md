# API/MCP 隔离持续验收（2026-10-19）

本轮专门补充持续负载与受控撤权证据，不替代 2026-10-15 的已授权物理主机记录，也不修改用户现有 API 客户端、权限、连接或网络。

## 可复现脚本

- `scripts/api-isolated-soak.ts`：默认 15 分钟、三个命名调用方、两个真实 SSH/SFTP 回环夹具。每轮 36 次串行基线与 240 次、12 并发混合请求；包含文件分页、64 KiB 分块读取、指标读取与唯一文件创建。每五轮旋转一个专用调用方令牌，验证旧令牌返回 401、该调用方重新认证连接、另一调用方原会话继续读取成功。记录每轮分位数、CPU、内存和事件循环延迟。服务停止后断言两个 SSH 夹具连接数都为零。
- `scripts/api-mcp-soak.ts`：默认 10 分钟，三个真实 MCP SDK Streamable HTTP 客户端，经渐进工具 `invoke_capability` 调用目录能力，保存分位数与资源样本；最后撤销一个专用令牌，确认该客户端失败、另一客户端继续成功。
- `scripts/api-soak-summary.mjs`：从完整证据汇总数字，Windows 句柄采样与进程内采样分开。

测试只在临时目录写入并在退出时清理。测试加密器为夹具编码实现，不是生产凭据加密。短回归使用 `tests/mcp.test.ts`、`tests/api-foundation.test.ts` 和 `tests/api-local-files.test.ts`，覆盖审批竞态撤权、饱和时控制通道、跨身份会话/任务隔离、输出保留缺口、取消及未知结果、审计不可用时拒绝执行。

## 范围边界

这些是真实协议与实际服务实现，但 SSH 主机为回环夹具，指标内容为夹具数据。内存和 CPU 包括测试调用端、夹具端、审计以及结果保留。十余分钟持续通过与连接归零只能补充回收证据，不能证明小时或天级无泄漏，也不能代表公网、多物理机器、真实桌面终端输入延迟或网络故障风暴。

初次 MCP 长测脚本遗漏必需的 disclosure 配置，随后使用了渐进模式中未导出的直接工具名；均属于测试脚本初始化错误，修正为完整配置和 invoke_capability 后重新从零计时。没有将失败的启动轮计为通过。

## 实测结果

两路脚本均退出码 0，17 项生命周期回归全部通过，类型检查通过。
