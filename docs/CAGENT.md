# cagent（Canp Agent）

cagent 是独立的精简本地智能体，同时保留 CShell 代理端角色。主界面围绕任务、应用市场、远程连接和设置，不复制 CShell 的服务器工作台、文件编辑器和多终端布局。

## 0.6.9 第一阶段已实现

- 独立 Node 运行时，无 Electron/Chromium 依赖。Windows 的 `Cagent.exe`、`cagent app` 或 `cagent-app.vbs` 打开原生 WPF 极简小窗，可置顶；会话、应用、模型与权限收进菜单，切换保留输入草稿。不使用浏览器或 WebView。其他平台暂保留系统浏览器入口，尚未完成原生界面。
- 独立模型基座，兼容 Chat Completions 流式接口；API Key、设置、最近 30 个任务通过原有私有加密 Vault 保存。界面不读出已存密钥。
- 本机环境、应用目录、本机命令工具。命令权限默认关闭，开启后默认逐次批准。命令使用真实检测到的 Shell，并受输出、执行时间和取消限制。
- 单个运行任务，每任务最多 8 次模型调用、每轮最多 8 个工具，15 分钟总限制。重启标记未完成任务为中断，不自动重试副作用。配置变更和委派撤权会停止活动任务。
- 提交任务必须提供 UUID `requestId`；同一控制端相同 ID 和正文返回原任务，参数冲突拒绝。去重范围为保留的最近 30 个任务，超出保留范围不能据此保证去重；调用方遇到未知结果应查询原任务，不应自动换键重试。
- 应用市场复用真实包管理器目录、检查、安装计划、显式执行、日志与取消。安装权限独立于命令权限；模型目前只能读取目录，安装由用户在计划页执行。
- 远程代理身份、终端和管理协议保留。`assistant.start/tasks/task/cancel` 提供任务委派接口，需要原远程管理权限与本机配置的委派控制端指纹同时满足；任务按控制端隔离，远端不能批准本机审核或修改模型配置。
- 本机页面只监听随机 loopback 端口，检查 Host、Origin、随机令牌和固定方法集合，不对外开放网络。控制面原有 IPC 仍拒绝浏览器 Origin。页面无外部脚本和分析服务。

命令以当前系统用户权限执行，不是权限沙箱；其权限可能覆盖该用户的文件、应用和配置。远程委派仅适合明确可信控制端。不能将程序级授权描述成对同用户任意代码的安全隔离。

## 应用与工具的长期契约

应用市场的单位是应用能力包：系统应用安装配方、适用平台与版本、安装后检查、配置入口、工具契约、所需权限、升级与卸载策略。依赖应用和工具包装器分别记录版本与状态，不能把“软件安装成功”当成“工具可用”。

能力状态应区分未安装、已安装未配置、待授权、可用、版本不兼容和故障。仅在依赖检查、配置与授权都成功时将具体工具加入智能体目录。工具 schema、调用与错误语义由同一注册表生成，界面和远程代理复用。

安装应用不会自动授权工具。应用可推荐所需权限，但用户在独立权限页选择并保存。升级保留原权限上限，新增权限保持关闭；卸载先停订阅与任务，再撤销工具注册，用户数据单独决定是否保留。

RDP 控制、Clash、微信等应成为这样的应用能力包，而非写入 cagent 通用导航。Clash 网络与代理设置必须单独授权、展示原值和计划并可恢复；RDP 客户端连接与远程桌面控制是不同能力，不能混称。微信现有 CShell 工具包尚未迁入 cagent 独立运行时。

## 兼容迁移

产品显示名改为 cagent，保留 `cshell-agent` 命令别名、原协议 ID、插件 ID 与数据目录。Windows 默认仍使用 `%LOCALAPPDATA%/CShell Agent`，避免丢失身份或重复初始化。不会因改名重建证书、读取 CShell 基座密钥、开放监听或扩大授权。

关闭原生窗口或浏览器页不会终止后台任务。使用 `cagent shutdown` 退出运行时。再次 `cagent app` 可重新进入；已存在运行时会复用它。

### 能力包市场界面（开发中）

从小窗右上角菜单进入“应用市场”。市场区分“能力工具包”与按需展开的“系统应用”，搜索同时过滤两类内容。原生 Windows 窗口与其他平台的浏览器后备界面共用后端返回的目录和状态，不列出尚未接入的微信、Clash 或自研远控占位卡片。

能力包详情显示来源、版本、核验状态和工具注册状态。点击“安装并核验能力包”后，权限仍需逐项勾选并保存；只勾选不会立即生效。系统应用安装能力还受独立的本机应用安装权限约束。支持重新核验、停用工具，以及内联确认卸载；卸载能力包不卸载此前通过它安装的系统软件。

系统应用保留检查、生成计划、显式执行、日志和取消流程。返回聊天保留输入草稿。原生面板发生错误时在当前面板显示，不再跳回聊天丢失操作上下文。

原生编译与隔离市场界面检查证据：`test-results/Cagent-market.exe`、`test-results/cagent-market.png`、`test-results/cagent-market.png.json`。这些检查不安装第三方系统软件，也不代表新市场已经完成本机更新或真实外部能力包验收。

CShell 的 cagent 应用市场也提供同一能力包目录。能力包安装、核验、授权和卸载仅在明确的本机目标显示；远端条目不提供本机管理操作。已安装的 `cagent.desktop` 包可展开桌面服务配置，本机观看、键鼠控制及各控制端的身份授权分别保存，默认关闭。改变监听配置会重启桌面服务并中断活动桌面连接；不会自动修改防火墙。桌面查看入口遵循后端实际 `viewAllowed` / `controlAllowed`，没有观看授权时不能连接。

`scripts/cagent-app-smoke.ts` 已覆盖浏览器后备界面的安装、无隐式授权、权限草稿、保存、停用、卸载确认，以及原有系统安装计划流程。`scripts/agent-capability-ui-smoke.ts` 验证 CShell 桌面配置默认关闭、观看与控制分离、保存前无调用、远端无修改入口和无观看授权禁止连接。测试均采用隔离后端，不安装系统软件、不连接真实远程桌面。

原生 Windows 市场的已安装桌面包详情还提供“桌面服务与访问权限”折叠配置：监听 IP、TCP/UDP、公网映射端口、本机观看/控制，以及按控制端指纹分开的远程观看/控制授权。保存才应用，默认不开启服务或权限；配置不经过 CShell 也可在 cagent 本机完成。原生隔离控件验证见 `test-results/cagent-desktop-settings.png.json`，不代表已在用户机器开启服务。

## Windows 一键部署包（0.6.12）

`CAgent-Setup-0.6.12-win-x64.zip` 是离线、当前用户安装包。完整解压后双击 `Install CAgent.cmd`，会核验全部程序文件，安装到 `%LOCALAPPDATA%\Programs\CAgent\versions\版本-摘要`，建立开始菜单入口，通过受限本机 IPC 检查后台；没有旧后台时打开 CAgent 小窗口。无需另外安装 Node/Electron，不申请管理员权限。ZIP 的 `.sha256` 用于从可信发布来源核对文件；尚无 Authenticode 签名。

最少配置步骤：

1. 安装后，在 CAgent 设置中配置连接密码、监听地址/端口，并按需开启远程管理。
2. 在应用市场安装“自研远程桌面”，分别配置观看和控制权限、允许的调用方。应用安装不代表授予权限。
3. 在 CShell 新建并保存 cagent 连接，首次核对设备身份后输入密码；完成授权后打开桌面。

部署包不自动开防火墙、不自动新增监听或访问授权，不改旧数据目录、设备身份、加密凭据及已有授权。采用版本目录并存，不关闭任何运行中的应用；若旧 CAgent 已运行，需正常退出后再从新入口打开才能切换运行版本。

打包命令：`node scripts/package-agent-windows-deployment.mjs release/0.6.12/agent-win32-x64`。输入必须是已经通过构建验证的 Windows x64 独立 CAgent 目录。新打包脚本独立于旧版 `package-agent.mjs`，保留旧发行附件命名兼容。安装器支持 `-Destination`、`-NoLaunch`、`-NoShortcuts` 用于隔离验收；生产默认创建当前用户开始菜单入口；仅确认无旧后台运行时启动应用。结果分别报告 `programInstalled` 与 `restartNeeded`（状态未知为 null），文件安装成功不等同于新后台已生效。

本机临时路径验证已覆盖首次安装、相同构建重复安装、文件损坏在创建目标目录前拒绝。证据：`test-results/cagent-windows-deployment.json`。此次没有访问任何公网服务器，也没有关闭用户应用。

## CShell Windows 安装包内置 cagent

Windows x64 的 CShell 安装包同时携带独立 CAgent，位于安装目录 `resources/cagent`。在已启用的 cagent 扩展、本机目标中点击“打开本机 cagent”，即可打开原生小窗口，无需另外下载 Node 或 CAgent。运行时仍使用原数据目录、设备身份和加密凭据；已有后台继续使用原会话，打开窗口不表示已切换后台版本。首次启动不会自动开启远程监听或授予能力权限。

`electron-builder` 的 Windows `beforePack` 会调用 `scripts/agent-build.mjs` 构建对应版本的独立运行时，`extraResources` 复制整个目录；`afterPack` 核对版本、平台、原生桌面摘要及全部复制文件。缺文件或版本不一致直接中止打包，不生成看似完整的发行包。构建主机需要 Windows x64 Node、.NET Framework WPF 编译器、LLVM-MinGW（可通过 `CAGENT_NATIVE_CXX` 指定）及 Node 许可证文本。未找到对应 Node 许可证时原构建脚本会下载官方许可证；离线构建可设置 `CSHELL_AGENT_NODE_LICENSE`。

针对检查：`tests/bundled-agent.test.ts` 验证复制完整性、旧代码拒绝、缺少运行时和版本不一致；真实独立目录完成文件核验。最终安装包及本机安装验收由发行流程执行。
