建议顺序：先解决稳定性与账号绑定、数据库所属线程调度，再完成通讯录/群成员/会话读取；随后接好友请求读取、备注修改和置顶；最后逐项验证加好友、处理申请、删除好友与群管理。媒体与消息历史独立推进，不能因为文本发送成功就认定共享同一契约。

新增工具需按行为独立授权，例如 `friend_requests.read`、`friend_requests.accept`、`friend_requests.reject`、`friends.add`、`contacts.update_remark`、`conversations.set_pinned`、`friends.delete`。这些名称是设计候选，尚未注册。改状态使用明确期望值（如 `pinned:true/false`），不用不可安全重试的 toggle；申请和删除等有副作用的调用必须保留幂等与未知结果。原有对指定联系人/测试群的文字收发授权不自动扩展为删好友、拉黑或群管理测试授权。

## 工具包边界

## 每次客户端更新的操作步骤

1. 保存上一版可用 profile、完整测试报告及工具包摘要。不要在用户正在使用的客户端自动降级、覆盖或杀进程。取得新旧安装包，验证官方签名，离线提取模块，记录版本、架构、SHA256。
2. 运行 `maintenance/compare_versions.py` 对旧 profile 的函数样本进行指令级比较，掩码仅限相对调用/跳转和 RIP 相对寻址。它只输出候选，不修改生产 profile。零匹配、多匹配或边界不符一律人工复核。
3. 从 SendEntry 调用图、工厂/构造/析构链、对象字段写入、消息向量步长交叉验证 ABI。不得只平移 RVA，不使用旧大小猜测新对象，不伪造 shared_ptr，不把日志路径当业务入口。
4. 先在独立夹具验证加载/卸载、并发回调、队列压力、取消与退出；再在用户明确的测试账号/联系人/群上做有时限探针。挂载前核对内存代码与磁盘模块，结束后验证原始字节及进程状态，继续观察是否延迟崩溃。
5. 分别验证私聊与群聊的发送人、会话 ID、正文、去重 ID、时间、类型；中文、emoji、换行、长文本、重复相同正文不能相互混淆。群消息需两位成员验证，@消息独立验收。发送调用返回与用户实际收到分开记录。
6. 通讯录必须从稳定数据服务或受支持数据读取入口枚举，并检查总数/分页/新联系人/删除/备注变化/群成员变化。内存缓存只能标记不完整，不可悄悄替代完整列表。
7. 分别测试注销、切换账号、断网恢复、进程退出/重启、插件撤权、重复请求、未知发送结果、异常正文和慢消费者。记录消息丢失、重复、CPU/内存/线程句柄、事件延迟及卸载后的稳定性。不能只测一次收发。
8. 为每项能力保存证据、限制和输入输出 schema，通过的能力才解封。版本/hash 不匹配时明确拒绝；不把启发式扫描结果自动下发为可执行地址。
9. 生成依赖锁定的 wheel/ZIP、文件 SHA256 清单、第三方许可证，验证全新 venv 离线安装。先本机显式安装验收，再按用户授权发布 GitHub。没有上传不得称“已发布”。

## CShell 本机实验扩展（2026-10-17）

插件市场安装“微信（实验）”，在独立工作区选择本机微信进程，分别配置发送、实时接收、历史读取目标并保存。智能体访问权限中的“微信读取 / 微信发送”是另一层授权；切换远端标签不改变微信所在机器。默认关闭，不把历史授权从接收授权自动继承。离线包当前携带 Windows x64 Python 3.12 的依赖轮子，需使用 Python 3.12 安装。

CShell 后端通过固定路径的本机 Python 子进程调用 `cshell_wechat.desktop`，没有监听网络端口。只有当前精确模块摘要和进程创建时间匹配才调用；重启微信后需要重新绑定。允许列表用内部 ID 或 filehelper，不能凭备注猜测收件人。发送保持先记 unknown 的持久幂等日志；取消和超时不能撤回已经提交的消息，不自动重试。当前仍是实验适配，已知崩溃风险未被隔离。

当前智能体工具：`wechat_status`、`wechat_contacts`、`wechat_send_text`、`wechat_receive`、`wechat_history`。好友接受候选仍只在本机维护入口，没有把未经完整验证的删除、拒绝、置顶等标记为可用。普通 CLI 的 live quarantine 保留；桌面实验通道必须显式授权，不代表稳定性验收完成。

历史读取是真实数据库查询，不是监听缓存：在数据库自身线程触发只读 SQL，最多 30 条，约 30 秒等待读取活动，原生查询预算 100 ms / 64 KiB。空闲时可能返回 HISTORY_UNAVAILABLE，需要打开对应会话或滚动历史后重试读取。查询不提取数据库密钥，不执行任意调用方 SQL。文本支持已核对的 UTF-8 与 Zstandard，媒体只返回元数据。解压、记录尺寸和返回量均有界，过大或未知编码标记 contentStatus/gap。

首次 direction=latest；向前翻页用 olderCursor + before；增量续读用 newerCursor + after。结果按 local_id 升序，64 位 ID 保持字符串。调用方须处理完成后持久保存游标，并按 deduplicationKey 去重；工具不会自动提交消费进度，不会启动后台同步。重启后重新绑定同一账号进程再沿用游标。数据库路径范围改变或游标锚点消失时明确拒绝或返回 gap，不能把空结果误当成已经同步。覆盖只限本地 message_0.db；其他分片、删除记录、远端未落盘消息未覆盖，complete 恒为 false，不提供完整补偿保证。

## 修改好友备注（2026-10-17）

## 0.6.3 / 工具包 0.1.1：主动数据库读取

正式桌面历史与通讯录读取不再依赖用户打开页面。先在有效协程上下文中调用微信自己的只读服务，以产生目标数据库工作，再在数据库所属线程执行固定、有界、经 stmt_readonly 校验的查询。没有在任意后台线程操作微信现有的 NOMUTEX SQLite 连接，也没有提取密钥或修改数据库。

当前精确版本的消息查询入口为 0x390bd10（CoQueryMessageBySvrId），输出为共享 future；使用目标会话、只读查找 ID 1 和限定分片参数触发本地查询，释放 future。通讯录沿 get_coro → get_svc → get_contact，使用服务 +0x1a8 的数据库服务调用 0x3015dc0，并释放 future 与服务引用。get_coro 钩子先检查有效 TLS 协程；读 SQL 仍在 SQLite reset/finalize 所属线程执行。原生查询、触发函数的活动回调共同计入卸载检查。等待仍有上限，服务不可用明确失败，不要求用户点击页面来掩盖失败。

`wechat_contacts` 从 contact.db 按 id 分页，limit 1–100，游标绑定数据库路径摘要，跨账号路径拒绝续读。返回原始 flags/deleteFlag/localType，不猜测好友关系；保留重复昵称，返回 hasMore 和 nextCursor，非快照，不宣称完整好友数。联系人权限默认不变，仍须显式允许读取。历史保持 message_0.db 的范围、文本解码、缺口和提交游标语义；不自动扩展到其他分片。

真实只读测试连续三轮：每轮读文件传输助手历史和 50 条通讯录记录，合计约 1.6–2 秒，未要求用户切页，没有发送消息；两种入口分别确认 SQLITE_DONE、codeRestored 和 unloaded。记录只保存计数、耗时和清理状态，不分发联系人、历史正文或数据库路径。该短期测试不能证明长期无泄漏或无崩溃。

升级适配需重新核对消息查询参数、future 所有权、联系服务 +0x1a8 的布局和线程上下文，先做只读验证与清理检查，不能仅换 RVA。微信重启仍要求重新绑定，常驻监听与自动账号重绑未完成；不得将此版本描述为完整无人值守守护进程。
