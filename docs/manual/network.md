<h2 id="choose">先分清要改变哪条网络路径</h2>
<p>模型请求、机器浏览器和远端应用分别选择网络。更改其中一项不会修改系统代理，也不会替所有程序接管网络。机器出口属于 Pro 会员能力，手动代理可在各版本使用。</p>

<h2 id="model">让本机模型使用另一台机器的网络</h2>
<ol><li>在出口机器上运行 CAgent，登录与 CShell Pro 相同的会员账号，确认设备在线。</li><li>打开设置中的「模型请求的网络出口」，选择「机器出口」。</li><li>从实际设备列表选择出口，核对页面路径为 CShell → 所选机器 → 模型服务并保存。</li><li>重新建立模型连接，再进行连接测试。已运行的请求不会被迁移。</li></ol><p>列表没有设备时，先检查账号、会员权益、CAgent 版本和在线状态。出口不可用时请求会失败，不会悄悄改走本机网络。官方模型、第三方扩展或独立客户端可能有自己的请求实现，不应仅凭此设置推断其网络路径。</p>


<h2 id="manual">使用现有 HTTP / SOCKS5 代理</h2>
<ol><li>选择「手动代理」，填写完整地址，例如 <code>http://127.0.0.1:7890</code> 或 <code>socks5://127.0.0.1:1080</code>。</li><li>当前支持无需认证的 HTTP、HTTPS、SOCKS5 代理。端口应使用代理软件实际提供的端口。</li><li>保存后重新测试模型。恢复时选择「直连」并保存。</li></ol><p>这里的 127.0.0.1 是运行 CShell 的这台电脑。不能把远端机器上的回环地址直接作为本机代理。连接拒绝通常表示地址错误或该端口没有代理进程监听。</p>


<h2 id="remote">A 机器使用 B 机器作为应用出口</h2>
<ol><li>两台 CAgent 登录同一个会员账号，保持在线。</li><li>进入 A 的机器桌面，在设置中打开「网络出口」。核对「当前机器」确实为 A。</li><li>选择 B，保存并等状态变为已连接。B 自己不会作为自己的出口选项。</li><li>需要在终端使用的程序应新建终端，且程序需要支持 <code>ALL_PROXY</code>。已有终端的环境变量不被改写。</li></ol><p>这不是全机 VPN；UDP、系统服务及忽略代理变量的程序不因此改道。保存失败时检查设备权限、会员状态与连接，不通过关闭安全校验来强行连通。</p>


<h2 id="latency">测量本机到目标、或 A 到 B 的延迟</h2>
<ol><li>展开「连接延迟测试」，选择「来源机器」与「目标连接」。来源只列出当前能执行检测的环境。</li><li>核对显示的目标地址和端口，点击「开始测试」。</li><li>查看平均、最快、最慢和失败样本；测试中可以取消，离开页面也会取消所属检测。</li></ol><p>每轮 5 个样本，每次超时 2 秒。数值是包含地址解析的 TCP 建连时间，不是 ICMP Ping，也不是文件传输速度或远控帧延迟。失败不会算成 0 毫秒；全部失败时不能据此判断机器关机，也可能是端口关闭、防火墙或路由问题。</p>
