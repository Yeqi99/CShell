# CAgent 自动化

自动化位于 CAgent 本机菜单。支持指定时间、固定间隔（至少一分钟）和精确来源/类型匹配的事件规则。它是通用智能体任务调度，不预置微信或课堂任务。

## 开始使用

1. 在设置与权限启用“允许管理自动化任务”。该权限默认关闭，独立于命令执行和远程委派授权。
2. 在自动化页展开“新建任务”，填写名称、任务说明和触发条件。界面新建先保存为暂停状态，再点击启用。
3. 在任务卡片中查看内容、暂停、停止当前运行，或展开删除确认。运行记录区显示实际任务状态。

智能体可通过 `automation` 工具创建、列出、暂停、取消或删除规则。已有自动化管理授权且不要求审核时，可直接创建启用的规则；要求审核时，变更须先通过原有审批。规则不能授予命令、应用能力或远端权限。运行时重新验证原创建者身份和当前授权，撤权后停用。

## 执行与恢复

规则和运行记录通过 CAgent 私有加密 vault 保存，不属于外观配置，不随云端外观同步。指定时间按界面当地时间转换为绝对时间；间隔以运行时刻推进，离线期间不补跑积累次数。当前智能体忙时，定时任务等待空闲；事件任务进入最多 100 项的持久化等待队列，默认等待五分钟，可在规则中配置最长一小时。到期明确记为“已过期”，队列满明确记为跳过；未开始的等待事件可在重启后继续，而已开始且结果未知的任务绝不重放。暂停、删除或撤销授权会清理待执行项。

执行前先持久化 occurrence 和唯一 requestId，再启动智能体。保存失败即停止调度。服务关闭会请求取消当前任务；这不代表外部操作已经撤销。启动时发现上次仍运行的记录，标记“结果待核查”并暂停对应规则；未知状态不会自动重放，先检查智能体历史和目标状态再决定后续处理。

每条规则至少间隔一分钟，全局每小时最多 60 次运行；最多保存 100 条规则、最近 300 条运行记录。删除规则保留已有记录。事件去重保存最近 1000 个来源/类型/事件 ID 组合，扩展发送者必须提供稳定唯一 ID，不能把本机有限去重窗口视为跨历史永久事务保证。

## 扩展事件桥接

后端 `emit(source,type,eventId,payload)` 仅供受信任集成和本机受限控制通道。页面和模型不能直接伪造事件。规则按来源和类型精确匹配，可附加 JSON 字段等值筛选（支持嵌套路径），例如指定 conversationId、senderId 或 isSelf=false。缺少字段不会匹配，也不凭空假定哪条消息来自自己。自动回复应设置自身消息排除和目标会话筛选，配合限流避免回复循环；事件正文只作为不可信上下文，不得覆盖任务或权限。正文 JSON 上限 8000 字符，事件 ID 上限 200 字符。扩展应固定来源、白名单事件类型，在进入自动化前完成身份验证和有界摘要。

## 验证范围

单元回归覆盖持久化预约、重启未知状态、作用域、撤权、审核、保存故障、重复事件、连续事件排队、重启保留等待项、队列容量/过期、字段筛选、暂停撤权清理及取消。实际本机 HTTP 页面在 1000 和 360 像素宽度完成新建、启用、暂停、无横向溢出和无脚本异常验证；UI 使用隔离模拟 vault/能力，不代表真实第三方扩展端到端已验收。

## 受管扩展入口

已安装且有真实校验目录的微信版本包在市场详情提供本机 API 配置、显式进程选择、绑定及验证。API 默认关闭，监听仅本机回环；业务范围设置和工具能力授权取交集。验证要求用户明确授权 API、事件读取及 filehelper 接收范围，不自动填写或放开范围。

扩展的可信回调桥将已验证事件交给通用自动化，固定来源 `extension.wechat`；正文仍标记不可信。只保留有限身份/会话/方向字段和有界文本摘要。优先保留原始事件明确提供的 `isSelf` 布尔值；没有该字段时，仅将明确的 `direction=incoming` 映射为 false、`outgoing` 映射为 true，未知方向保持缺失。筛选示例仅是提示，不会自动写入规则。市场详情可跳转通用任务页，不把订阅与定时任务写死为某个业务。

公开目录未包含已构建且核验的对应包时，不显示安装入口。绑定、版本隔离、验证失败或权限不足都不应显示业务能力可用。配置 UI 的隔离模拟验收不等于真实微信消息收发验收。

## CLI

现有 `cagent call METHOD` 从标准输入读取 JSON，经本机认证控制通道调用同一后端，不需要另一套微信 CLI 实现。例如 PowerShell：

```powershell
'{"id":"cagent.wechat.v411556"}' | cagent call managedWechat.status
'{"id":"cagent.wechat.v411556"}' | cagent call managedWechat.processes
'{"id":"cagent.wechat.v411556","pid":1234}' | cagent call managedWechat.bind
'{"id":"cagent.wechat.v411556","pid":1234}' | cagent call managedWechat.validate
'{}' | cagent call automation.list
```

PID 必须替换为进程列表中明确选择的真实 PID。`managedWechat.configure` 接受 `{id,settings}` 完整设置对象，服务端严格校验；配置结果不包含 API token。自动化还支持 `automation.create` 和 `automation.change`，与页面执行同一授权、持久化和取消路径。
