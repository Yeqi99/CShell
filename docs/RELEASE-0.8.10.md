# 0.8.10：配置同步与多面板修复

0.8.10 已正式发布；GitHub 标签、全部附件及香港分平台更新渠道已核验。 不代表所有设备已经安装。

## 同步与兼容

- Pro keyed-array 合并保留实际排序，避免连接等列表仅按 ID 恢复内容却丢失顺序。
- Android 不消费的 FTP / SFTP 配置保留原位置与未知字段，不转换协议或清除桌面配置。
- Tavily 的账号和 Key 通过加密账号段同步、导入；allowPaygo、扩展安装与权限留本机。未配置时省略段；明确删除最后一个账号保留空墓碑；旧云缺字段不覆盖本机；失败回滚恢复原快照。
- 机器桌面 Look 已实现可选加密 `desktopLooks` 段：`looks` 以稳定 device/profile ID 保存 name、theme（light/dark）、wallpaper（coast/dusk/forest/ink）、可选 imageId；`null` 是恢复默认墓碑。`images` 以 SHA-256 对应 PNG/JPEG/WebP data URI。排除 windows / native 临时状态。本机存储为加密 desktop-looks.enc，Pro 使用相同可选段同步。
- 背景图片校验格式、魔数、规范 base64 与摘要；单图 data URI 至多 4M 字符，整段至多 8 MiB / 1000 台机器，账号自身总容量限制仍有效。仅首次迁移当前账号已有非默认 localStorage Look，后端、云与重置墓碑优先。
- 显式来源导入只有选择外观设置才纳入机器 Look，逐机器选择冲突；旧来源无段保留目标配置。使用原应用上下文解密、目标上下文重加密，失败沿整体云快照回滚。
- 完全空的 Tavily / 桌面外观账户省略新增段；实际配置或明确删除墓碑才输出。普通同步缺段不清本机，回滚快照缺段时恢复为空。桌面图片按最终引用回收，合并保留另一端仍引用的同摘要图片。
- 带新可选段的账号需要新版桌面客户端。0.8.9 的严格解析安全拒绝未知段，不删除云端；没有新段的账号正常兼容。不能通过丢弃新段来伪装旧版兼容。

## 界面与交互

- 修复 SSH 右侧文件与基本信息被智能体面板强制隐藏；恢复入口和窄宽共存，保留终端、编辑草稿与当前连接归属。
- 模型菜单键盘焦点、空搜索结果与菜单定位；异步目录刷新不替换运行会话模型。
- 命令台异步结束不夺走其他输入焦点；保留已有目录、任务结果和取消语义。
- OpenCode 默认模型按钮改名为“设为默认模型”，不把配置默认值当作实际推理检测。

## 已有性能证据与限制

SSH TCP 建立后显式设置 `setNoDelay(true)`，消除客户端 Nagle 小包合并等待；网络 RTT、服务器处理与屏幕显示延迟仍存在，尚未确认它就是用户反馈的根因。[Node net 文档](https://nodejs.org/api/net.html#socketsetnodelaynodelay)说明新 TCP 连接默认启用 Nagle；本轮使用的 ssh2 未自动关闭。两版真实 SSH fixture 专测确认认证前对实际客户端 Socket 设置禁用 Nagle，逐字符输入与回显正确且只建立一个连接；连同连接取消、超时、断线、四会话输出和 SFTP 错误回归，各 **8 项通过**。没有以固定延迟阈值或局域回显推断公网改善幅度。

2026-10-25，真实 Pro 0.8.9 包的本地 DOM 基准：原始 SSH p95 **19.2 ms**，可视化 p95 **21.6 ms**。这是 0.8.9 的测量基准，不是 0.8.10 的改进百分比；它衡量本地输入处理与渲染响应，不等同于用户公网往返、目标机器负载或物理屏幕端到端时延。原始和可视化均为直连 SSH，未通过 CAgent。不能据此声称用户网络延迟已消除。
