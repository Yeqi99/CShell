# 0.8.17 更新与微信扩展

状态：0.8.17 首轮候选已构建并安装到本机；新增更新体验修复后正在重新收尾，GitHub 应用发行仍为草稿，尚未公开。独立微信工具包 0.1.1 已公开并通过匿名安装链路验证。

## 更新下载

香港源返回 522 或超时时，客户端可从官方同渠道 Release 继续查询和下载。下载仍校验版本、架构、大小与 SHA-256，不打开浏览器，不混用普通版与 Pro 安装包。CAgent 的更新请求使用系统或环境代理，配置的代理失败不回退直连；暂不支持的 PAC/WPAD 明确提示。

为恢复旧客户端，下载域名的两份目录及 0.8.16 附件由独立边缘服务提供。只接管这四条路径，网站其他服务与 DNS 源站不变。香港源站现已恢复，真实 SSH 与 HTTPS 请求返回成功（HTTPS 200）；先前的源站不可访问记录属于恢复前状态。边缘回退保留，0.8.17 公开前仍须核验对应目录与附件白名单，不能把源站恢复视作新版本已公开。详见 [更新源恢复](UPDATE-SOURCE-RECOVERY.md) 和 services/update-edge 的验收记录。

## 本轮追加的更新体验修复

- 下载进度复用文件传输的字节格式，Web 与 Windows 原生窗口统一显示 KiB / MiB / GiB；总量未知时明确提示，不用零冒充总大小，后台保留精确字节计数。两树各 10 项更新回归、类型检查及原生 C# 编译通过。
- 已有安装显示“更新 / 修复”，呈现已安装版本、目标版本与原安装位置；首次安装仍显示“安装”。CAgent 优先保留自身既有安装位置，显式指定目录优先；准备阶段不注册安装，不改变用户数据或权限。两树通过真实 NSIS 编译与隔离目录识别回归，不等同实际用户安装器全视觉验收。
- 修复原生更新界面调用 `update.verify` 时被本机桥接遗漏的问题。验证操作仍检查 Origin 与 Token；内部 `update.commit` 不向页面开放，未认证调用不能触达运行时。

- 下载响应开始后若连接中断或超时，最多尝试 3 次，后两次固定使用官方同渠道同名附件；关闭应用取消时不重试。所有尝试仍校验大小与 SHA-256，异常附件不进入可安装状态；最终失败给出中文可恢复提示。两树各 11 项更新回归与类型检查通过。

以上是首轮候选之后的产品变更，需重新冻结源码、构建并核验附件；不能用先前 CI 或本机安装记录冒充这些变更的最终成品验收。

## 微信扩展

支持精确版本 4.1.15.56、4.2.0.12 的独立工具包。源码保存在私有仓库，市场安装公开二进制；配置、授权和账号绑定仍分别完成。文本收发与事件可接入通用定时任务和事件处理，不把业务任务写死在客户端。

原生验证超时不会强杀回调进程。结果未知的操作保留状态，不自动重试；不同微信版本与进程创建时间隔离。市场下载采用系统代理、有限大包超时及完整摘要校验。

## 本机到目标服务器的 Ping

侧边栏与资源面板仍向所选连接的实际地址发送 ICMP，不使用 localhost，也不把 SSH/TCP 往返时间当作 Ping。Windows 先以 Find-NetRoute 查询该目标的实际出口；若经已识别的 TUN/代理接口或 198.18.0.0/15 合成地址段，显示“代理路径”，不显示可能由代理本地应答的毫秒数。悬停可看目标 IP、接口及原因。路由无法确定则显示“路由待确认”；不自动关闭代理、更改路由或绕过用户网络配置。

2026-10-31 本机只读实测：ping.exe 向香港、美国和主力服务器分别返回约 0–2、4–6、0–1ms，TTL 均为 64；其中目标美国服务器的实际路由为 Meta，源 198.18.0.0、下一跳 198.18.0.1。修复后三个实际目标均返回 proxy-path、elapsedMs=null，回环仍正常返回真实 ICMP 回应。低耗时和 TTL 本身不是判假依据，判断依据是所选出口。

两树各 4 项 Ping 测试与类型检查通过，包含所选真实 LAN、普通物理出口、IPv4/IPv6 回环、合成地址、未知路由与 Wintun fixture，以及实际回环与 IPC 目标约束。没有实测远端直连延迟，也未改变本机网络。此防护覆盖 Windows 已识别的代理路由，不宣称识别所有第三方代理；非 Windows 原有 ICMP 路径尚未增加同等路由诊断。
