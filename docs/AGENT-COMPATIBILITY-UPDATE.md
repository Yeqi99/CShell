# CAgent 能力兼容与安全更新

## 旧机器的硬件信息和应用市场

SSH 连接沿用已认证的同一机器、同一用户，通过独立 SSH 通道访问已安装 CAgent 的受限本机控制口。客户端携带固定版本的桥接代码，旧桥接程序不再先用旧方法枚举拒绝新请求；不会覆盖远端程序、启动第二个身份库或关闭现有终端。

新 CAgent 在状态中提供实际版本和方法列表。旧后台确实不支持硬件信息时，SSH 连接通过原有私有 Node 或系统 Python 3 进行只读采集；未安装采集运行时则给出明确错误，不自动安装系统依赖。CPU、内存、磁盘、接口、进程等来自实际系统命令和 `/proc`。没有 GPU、驱动或读取权限时显示缺失原因，不填零假装成功。权限拒绝、断网和结果不明不触发绕行或重复变更。

SSH 应用市场继续使用已有的独立 SSH 安装计划服务。检测、计划、明确执行保持独立，沿用目标用户的权限，不自动 sudo。CAgent 市场某一读取失败不再抹去其他成功读取的能力。

## 自动更新的边界

支持更新协议的新后台会检查并下载适配当前平台和架构的正式附件，验证 SHA-256。实际终端、正在打开的终端、命令、模型任务、应用安装、IDE、上传、浏览器通道、桌面流、能力包调用、WSL、托管服务、连接和中继都参与活动检查。Pro 另外检查云同步、代理流量和账号中继。不能证明外部扩展空闲时保持等待。

后台连续空闲 30 秒后开始准备，15 秒调度再次检查。准备过程中出现新工作会延期；候选版本变化会丢弃旧准备结果。关闭新任务入口后再次检查活动，才开始停止旧后台。用户点击更新也遵循此规则，不强制切断任务。

- Windows：安装器 `/PREPARE` 只校验并放入独立版本目录，不改快捷方式、不启动和关闭程序。随后原子替换启动入口，使用新私有运行时启动后台。
- Linux/macOS：归档必须为当前系统/架构、无越界路径和链接，私有 Node 与原生依赖预检通过后，再原子切换程序目录或安装链接。
- 新后台以一次性本机交接凭据启动，暂不接收新工作。受限 IPC 必须证明同一设备身份、目标版本和更新协议，才开放入口。启动核验失败会恢复旧程序并验证旧后台身份和版本。
- 提交响应丢失时只读复核。无法确认的提交不重放，也不杀掉可能已接收任务的新后台；保留新旧版本。未完成交接的新后台 60 秒后退出，恢复结果会在可确认时写入本机更新记录。
- 回滚前先记录失败版本，恢复的旧后台在 6 小时内不会再次自动安装同一版本，避免循环重启；更新的版本不受此限制，用户仍可显式重试。

旧后台没有活动协议时不能把“连接数为零”当作空闲，也不会偷偷重启。上述 SSH 兼容读取和应用安装仍可使用；其首次迁移需要在确定没有活动任务后使用新版安装包。后续才具备完整的自动空闲交接能力。Windows 首次旧版迁移、Linux/macOS 实机发行包验证和系统签名限制需要在发行记录中分别说明。

## 本轮验证

- 真实香港 Linux 主机：固定 Python 3 采集与独立 hostname、uname、MemTotal 读取核对通过；8 核，25 个接口，磁盘数据有效，GPU 明确不可用。没有安装依赖或重启服务。
- 浏览器组件回归：旧 Agent 局部失败不抹除可用市场；SSH 目标、计划、单次显式安装；硬件来源标识；390 px 无横向溢出。
- 更新协调器：真实资源忙、准备期间新增任务、候选版本改变、自动更新关闭、未知活动、关闭失败恢复、未知提交不重放。
- Windows：实际 PowerShell 准备安装、实际私有 Node 子进程和受限 HTTP 握手，成功交接与错误身份回滚均通过；不使用用户应用实例。
- Linux/macOS：真实 staged archive/回滚测试已加入，Windows 本机按平台跳过；需 Linux/macOS CI 执行。真实发布包和系统实机验证不由这些 fixture 测试替代。
