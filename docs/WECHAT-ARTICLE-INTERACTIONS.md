# 公众号文章互动：观察与实现边界

2026-10-20，在 Windows 微信 4.1.15.50 中观察用户指定的分享文章。

## 已实际观察

- 文章卡片在微信内置文章面板打开，不是独立私聊对象。
- 文章底部留言按钮打开侧栏，本样本显示 100 条留言；此数字不代表已读取全部记录。
- 底部“写留言”是文章级留言入口。
- 点击已有留言后显示回复图标；点击图标出现指向该留言作者的内联输入框与“回复”按钮。
- 回复框与新留言框独立。不能把私聊 send、朋友圈评论接口作为文章回复实现。
- 本轮只观察入口，没有输入或发布文章留言，也没有点赞。

## 当前实现

历史消息已解析 appmsg type=5 的标题、摘要及链接。该信息仅描述分享卡片，不提供全文、留言 ID 或发表能力。

尚未定位文章留言读写协议、微信会话授权上下文及请求结果；没有对外注册文章留言、回复或点赞工具。界面存在入口不等于原生接口已实现。

曾尝试 articles.py 的公开 HTML 读取，但真实样本遇到验证页/交互重定向，没有获得全文。用户明确要求微信内部原生访问，因此已从 Codex 全局工具移除 article_read；该实验模块不作为公众号功能实现或回退路径。

静态调查发现当前客户端包含 xweb_call_jsapi、xweb_call_geta8key_cgi、IWebViewJsChannel 与 XWebGetA8KeyReq/Resp；这些是定位线索，尚未验证调用约定，不得直接调用猜测地址或宣称已经完成认证链路。

在已核验的 4.1.15.50 DLL 上，静态引用定位到命令分发函数 RVA 0x935b60：xweb_call_jsapi 分支位于 0x93646c，xweb_call_geta8key_cgi 分支位于 0x93727e，后者调用 0x93bcf0。这些是静态分析结果，尚未进行原生调用或证明参数所有权。webviewHtml 对应 0x45b3680 的引用表现为 JSON 构造，不能据此认定可以读取文章正文。

下一步是限定单篇文章加载的只读观测，确认命令、参数结构及回调生命周期；不保存登录票据、不用猜测地址调用、不把验证码页视为正常文章，也不通过公开 HTTP 绕过客户端权限。

### 只读运行结果

用户在电脑微信刷新指定文章并滚动到末尾，确认本次页面的留言直接显示在文章底部，不需要单独打开列表。原生分发探针捕获 JSON 外层 `url`、`msg`；后者为 JSON 字符串，包含 `func`、`params` 与 `__callback_id`。实际出现 `H5ExtTransfer`，其参数含 `req_json`、`cgi_type`、`scope`、`url`、`webcgi_method`、`webcgi_header`，以及页面行为 API `handleMPPageAction`。这证明存在原生转发路径，但尚未证明哪条请求用于正文或留言，也未验证返回回调。

本轮已恢复入口代码并卸载探针，无保留会话或清理错误；只持久化结构，不存原始请求、会话票据、请求头值。静态引用进一步定位到 `0x45b7570`（同时引用 H5ExtTransfer 与 req_json）和 `0x457f600` / `0x3c10c60`（引用 req_json、webcgi_method）；它们仍只是待分析入口，不允许据此直接调用。

后续刷新观测已识别 `H5ExtTransfer` 的 `/mp/appmsg_comment` 路径，另有 `/mp/getbizbanner`、`/mp/jsmonitor`、`/mp/wapcommreport`。同一路径可能承载不同动作，不能只根据路径认定是读取或发表；`req_json` 本轮不是可直接解析的 JSON，下一步只提取表单字段名核对格式。此次清理同样确认代码恢复、脚本卸载且无保留会话。尚未执行原生发表。

## 后续验收

1. 定位文章身份与分页留言、回复数据，区分根留言 ID、回复 ID、作者身份及删除/待审核状态。
2. 分别实现文章留言和指定留言回复，保持文章权限与聊天发送、朋友圈发布权限独立。
3. 确认真实发送请求及返回含义；超时保留未知状态，避免重复发表。
4. 以用户指定文章进行单次自然内容验收，读取回执与实际留言结果；待审核不能宣称公开可见。
5. 当前普通读者入口不能冒充公众号运营者后台回复权限。
