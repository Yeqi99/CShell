### 本机端口与令牌隔离复验

Pro 独立端口的 Windows connect、desktop_status 成功，返回查看/控制已授权；desktop_screenshot 仍执行失败，远端会话检查为已断开、CAgent 0.8.14。未据此宣称独立远控已完成，未自动转移或解锁会话。

### Pro 独立 MCP 3778 复验及服务归属纠正

本次明确记录端口 `3778`，通过正式 MCP `connect → monitor → monitor → disconnect` 验证 Pro 0.8.16 的已有美国机器。用户已在 Pro 保存工具授权，本次测试未自行改变权限。

- 同一 MCP 客户端连续读取：首个网络样本为 `sampling` 且速率为空，第二个为 `ready`；返回采样时间相隔 4671ms。速率仍按远端 uptime 计算，不用本机调用耗时替代。
- `eth0` 接收 578.93 B/s、发送 1367.36 B/s；`lo` 真实差值为 0。CPU 型号为 `Intel(R) Xeon(R) CPU E5-2696 v4 @ 2.20GHz`，4 逻辑核心；内存、3 个挂载点和物理磁盘均有实际返回。正式 monitor 的后端权限检查与结果协议通过。
- 另一次两个独立 helper 调用相隔约 34.7 秒，超过 30 秒采样窗口，正确返回 `sampling` 与空速率；没有把过期基线当实时速率。
- 最后正式 `disconnect` 返回 `closed: true`。证据为 Pro 本地 `.local/network-pro-live-result.jsonl`（包含实际端口）及 `.local/network-pro-monitor-1.json`、`.local/network-pro-monitor-2.json`；不发布这些本地诊断文件。

主任务另已核对：两个应用的历史 MCP 令牌相同（仅比较相等与否，不输出秘密），这和端口同为 3777 共同造成服务归属混淆。令牌相同的来源尚未查明，当前导入/云同步白名单不复制该字段，不能据此归因于用户操作或当前云同步。Pro 已分离到 3778；主任务正在仅为 Pro 更换独立令牌，Core 保持不变。以上实测发生于令牌更换前，身份隔离完成后的验证须由主任务另记。
