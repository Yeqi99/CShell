## 免费版 / CShell Pro 划分提案

原则：现有能力留在免费版；Pro 为新增的运维效率和持续服务收费，不把安全、数据访问或已有功能变成收费入口。此表是产品方案，不表示 Pro 已实现或可购买。

| 范围 | CShell 免费版 | CShell Pro 新增能力 |
| --- | --- | --- |
| 连接与文件 | 现有 SSH、SFTP、多会话、本机终端、Client 连接、监控和配置管理 | 不以服务器数量或基础文件操作制造限制 |
| 插件与 MCP | 现有插件市场、Docker/Python 等能力、明确授权的 MCP | 官方维护的高级运维插件与成套任务模板 |

| 持续执行 | 应用运行期间的现有目标调度 | 明确安装和授权的后台执行器；关闭界面后继续运行，执行记录可追踪 |
| 审计与报告 | 现有执行记录、授权确认、个人数据导出 | 按任务/机器聚合报告、保留策略、结果通知和可导出的审计报告 |
| 手机端 | 现有连接、终端、文件与更新 | 后续查看 Pro 任务结果、接收通知及明确批准任务；首版不承诺桌面功能全部移植 |
| 团队能力 | 个人本地使用 | 团队资产、成员授权和集中审计放到后续 Team 阶段，不塞进 Pro 首版 |

### Pro 首版范围与顺序

1. 先做任务模板和批量运维：明确机器、步骤、完成条件、时间限制、失败策略及执行前计划；沿用现有后端权限，不让模板扩大权限。首批场景可包括服务巡检、日志整理和 Docker 停止容器清理。
2. 再做后台持续执行：复用现有工具协议和固定目标，一个轻量调度器按需唤醒任务，限制并发和资源；不为每个目标常驻一个进程。后台执行器独立授权、可停止、可卸载，不自动安装到用户机器。
3. 最后接入商业授权与交付：新增模块的授权/分发方式单独确定；当前仓库仍保留 MIT。授权在后端核验，支持离线宽限与设备管理。到期不删除配置、不关闭已有终端、不阻止读取和导出自己的数据；新付费任务按明确规则停止创建。
4. 定价、买断或订阅、设备数量、离线授权和服务承诺需在商业实现前确定。这一轮不加入登录墙、支付入口、占位 Pro 按钮或限制现有功能。

### 首个自动化场景的验收边界

“清理不活跃 Docker 容器”必须定义目标机器、容器筛选条件、停止时长和保留名单；低 CPU 不等于不活跃。先预览候选和理由，再按用户明确授予的规则执行；不自动提权、不开放 Docker TCP、不删除卷。断连、权限撤回、条件缺失时停止并留下原因。
