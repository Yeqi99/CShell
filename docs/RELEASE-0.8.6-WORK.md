## 退出残留的进一步定位与修复

- 诊断记录显示 `TCPWRAP` 来自 Node `internalConnectMultipleTimeout`：全局 fetch 的连接建立阶段可在取消后仍留下 TCP 句柄。改为更新专用 HTTPS 单次请求，禁用连接池复用、保持 TLS 校验、禁止重定向，并将取消信号绑定实际请求。没有修改其他业务的全局网络行为。
- app-host 在已认证运行时关闭并完成资源清理后释放自身 stdin；隐藏窗口不会触发此操作。第二个界面退出仍只关闭自身 UI 服务，不关闭第一个界面的后台。
- 新增真实 TCP/TLS 握手停滞测试，确认取消后服务端连接数归零；两版更新相关 5 项测试及 TypeScript 通过。
- 干净 CLI 构建的隔离 app-host 已通过退出验收（父进程 stdin 保持打开，不靠 kill 判通过）；开源连续复测通过，Pro 独立构建通过。新增第二界面关闭、主后台仍存活的生命周期回归。
- 仍需启动过程中立即关闭的竞态检查、原生窗口/托盘及升级全链路回归。当前不是正式发行构建，正式安装仍为 0.8.5；不把这组关联修复拆作三项来凑版本。

## 启动期间关闭的竞态（2026-10-24）

- 新增早关闭模式与可重现的隔离构建脚本，延迟本机 UI 初始化。修复前认证关闭后仍超时退出。
- 发现文件可能在权限保护步骤完成前被本机读取；关闭发生时 control 尚未赋值，原清理遗漏随后返回的控制服务。startControl 现在接到迟到句柄后检查关闭状态并释放它，不再初始化更新任务。
- CLI 保存运行时关闭状态，UI 初始化前后均检查；已经关闭的后台不会重新公布 UI 地址、恢复 stdin 或启动浏览器。
- 两版早关闭回归通过，保持父进程 stdin 打开；仅测试清理失败时才 kill，不把强杀算作通过。CLI 及运行时改动均同步 Pro，未动账号身份或权限策略。
- 仍属于退出生命周期这一组问题，不拆分成三个发行条目。发行前还需原生窗口及全套回归，随后选择有证据的其他缺口继续改进。
