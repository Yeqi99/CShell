# 文件大小与传输反馈验收（2026-10-30）

## 修复范围

- SSH/SFTP 与本地文件列表原先使用中文紧凑数字格式（如“1.4亿 B”），统一为 B / KiB / MiB / GiB。FTP、CAgent 使用同一格式化函数。
- SSH/SFTP 数据流、跨服务器复制及 FTP Provider 的真实字节回调进入统一进度计量器。队列等待不计入传输计时；显示明确标为“平均”的吞吐率，结束、取消和失败后清除速率。
- SSH 工具侧栏新传输自动展开队列，显示已传/总量、百分比和平均速度。目录逐项发现总量时只显示已传字节；文件提交/重命名完成之前不显示完成状态或 100%。
- CAgent 下载原先只有“正在传输”，后台写入每个真实分块后发送进度事件；剪贴板上传以远端确认的 offset 累计。批量总量未知时不伪造百分比。结束事件不受 100ms 节流影响，保留最后实际字节数。
- CAgent 浏览器文件选择上传在每次远端分块确认后更新真实计数与平均速率，并核对远端返回位置。取消、错误和目标切换不保留进行中的假速率。

## 美国机器真实 SSH/SFTP 验收与上传窗口调整

2026-10-30 使用 Pro 保存的美国机器（199.102.219.30）及既有 pinned SSH 身份，以产品 `SshService` 和 `Transfers` 队列进行验证，不使用独立上传工具冒充产品传输。

- 在 UUID `/tmp/cshell-transfer-*` 目录及本机临时目录生成 16 MiB 随机数据；真实上传、下载均完成，下载 SHA-256 与源文件相同：`5b908d135bb7c29599e15502bca5c2c7051c4b740a03c2045a3d2fd75b146866`。
- 上传 255 次、下载 256 次非零进度事件，累计字节单调增长，完成均为 16,777,216 字节，已知总量正确，过程中有正平均速率，结束清除速率。
- 另一次下载首次收到 65,536 字节后断开专用测试连接，结果为 cancelled，而非成功；结束速率清除。
- 所有测试目录先核对绝对 realpath；只清理本次生成的文件和目录，全部清理成功。没有修改用户配置、凭据、授权或既有会话。

该链路表现出低吞吐及波动：原路径一次上传末次平均 144,528 B/s、下载 28,059 B/s。发现 SFTP 写入默认小窗口会逐块等待远端应答，因此将上传及跨机复制的远端写缓冲限制为 1 MiB，利用 ssh2 原生批量写入；仍使用原 pipeline 背压、取消、独占临时文件及最终 rename。

调整后的独立 16 MiB 上传完成，末次平均 1,194,292 B/s（约为前述样本的 8.3 倍）。后续测试同一链路又出现明显等待，故不将一次测量当作稳定速度承诺。新并发下载尝试未通过真实验收，已撤回；下载保留已通过完整哈希与断连验证的原实现，其高延迟链路吞吐限制仍存在。

最终保留改动的测试：新增 2 项上传窗口测试验证有界批量写入、准确数据、提交前状态，以及写入失败清理且不 rename；加上原 8 项进度/取消测试通过。真实收据位于 Pro `.local/file-transfer-baseline-evidence.json`、`.local/file-transfer-upload-improvement.json`；后续取消诊断的清理收据为 `.local/file-transfer-real-evidence.json`。该验收不代表安装后的 UI、Windows/CAgent 或剪贴板批量路径已验证。
