# 扩展取消等待实际进程关闭

完整回归曾出现扩展取消后删除专用目录报 EBUSY。代码审查发现：Windows 取消仅等待 taskkill 退出，兜底终止也立即返回；进程已有退出码时直接返回。上述状态都不能证明子进程的流与句柄已经关闭。该问题已独立复现，但不据此断言首次 EBUSY 的唯一原因。

现从启动时就观察子进程 close 事件。取消、撤销授权、超时及正常返回后的清理，都在终止请求之后等待该事件；即使退出码已经存在，也等待流关闭。等待有三秒上限，超限明确报错，不假报清理完成。终止仍只针对自己启动的进程及进程树，不接收用户提供的 PID。

tests/process-extension-close.test.ts 验证：终止工具退出后调用不能提前结束；已有退出码仍等待 close；三秒未关闭则拒绝。前两项在旧清理逻辑下失败。tests/process-extensions.test.ts 保留真实子进程取消、撤销、超时、槽位恢复及权限隔离回归。

开源真实扩展回归 8 项及关闭时序 3 项分别通过；Pro 合并运行 11 项全部通过。两版 TypeScript 检查通过。

首次全量测试的其他启动与托管时限失败，另做文件串行复查，31 项通过（含真实 WSL）。该结果不证明并行争用为唯一根因，不删除首次失败记录，也不修改生产执行时限来使测试通过。本修复尚未发布。
