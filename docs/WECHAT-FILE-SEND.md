# 微信文件发送适配

当前开发适配：Windows x64 微信 4.1.15.50，模块 SHA256
`0cf6379405432385a1c442766443450f26a7689f45e53c1b4ad2822061f3113b`。
其他模块摘要不能使用这些偏移。

## 验证证据（2026-10-20）

- 对用户主动向文件传输助手发送的附件进行了单次、限时原生观察；探针卸载及代码还原均成功。
- 附件使用基础消息对象，工厂 `0x2c18c40` 分配 `0x768` 字节（含 `0x10` 字节控制块）；对象有效长度 `0x758`。
- 基础对象构造 `0x778e10`，虚表 `0x8ffec48`；收件人 `+0xb0`，类型/子类型 `+0x118 = 0x600000031`，UTF-16 文件路径 `+0x120`，UTF-8 文件名 `+0x1a8`，大小 `+0x1c8`。
- 调用链复用有 TLS 上下文检查的发送服务和 `0x17b3d70`。不能把文件路径作为文本消息发送，也不能复用文本子类的 `+0x758` 内容字段。
- 原生测试向文件传输助手发送了自行生成的小型 TXT；用户在手机上确认收到并能正常打开。此证据不代表大文件、所有文件类型或长期稳定性已验收。

## 工具契约

`wechat_send_file` 接收 `recipient`、目标机器上的绝对 `path` 和稳定的 `idempotencyKey`。
远端 CAgent 使用其机器上的文件，控制端文件须先通过文件传输能力上传。
需要独立 `sendFiles` 授权及既有收件人发送授权，黑名单优先；旧设置不会自动授予新能力。

发送前分块复制文件到桥接器的本地暂存目录，同时计算 SHA256 并检查源文件是否发生变化。
本版单文件范围为 1 字节至 128 MiB，暂存预算 512 MiB / 64 个文件，超额明确拒绝。
发送调用开始后保留暂存文件，避免异步上传读取到被修改或已删除的源文件。
未提交及重复调用产生的临时副本会清理；未知结果不会自动重试，也不会自动删除上传中的副本。

返回 `native_returned` 只说明原生函数返回，**不代表上传完成或对方已收到**。
同一幂等键且内容不同会拒绝；相同请求重复调用不会再次发送。当前幂等范围仍绑定微信进程会话，跨进程重启不得用新键盲目补发。

## 升级验证

1. 重新核对模块摘要、工厂、对象长度、字段编码、原生发送上下文及共享指针释放。
2. 使用 `maintenance/observe_file_send.py` 观察一条专用文件传输助手测试附件，输出仅留本机，不进入发行包。
3. 用生成的非隐私文件验证手机端接收、打开和内容；覆盖中文文件名、空文件拒绝、取消、重复调用、断网未知结果。
4. 新版本未验证前不得迁移旧偏移或宣称兼容。
