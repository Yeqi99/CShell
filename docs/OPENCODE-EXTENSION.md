# OpenCode 模型扩展

OpenCode 通过内置扩展 `cshell.opencode` 接入，需在插件市场启用。模型目录、协议转换、账号凭据与 Go 用量由扩展管理，CShell 智能体通过通用模型接口使用，不在普通基座表单中写死供应商。

## 配置账号

1. 在插件市场启用 OpenCode，打开配置页。
2. 点击“获取 API Key”进入官方控制台创建密钥；也可使用“通过浏览器登录”，在官方页面核对代码、选择工作区并批准设备授权。扩展不提取浏览器 Cookie。
3. 填入 Key，点击“保存并检测”。账号名和控制台工作区地址可选，最多保存 32 个账号。保存后调用认证配置接口验证账号、接入账号基座并尝试读取 Go 用量；不会自动发送推理请求。
4. 在智能体的新会话选择该 OpenCode 账号，再从账号模型菜单选择 Go 或 Zen 模型。一个账号对应一个基座，不需要逐模型添加。

已有账号可点击“接入此账号”。如需验证某个模型的实际权限及响应，选择模型后点击“检测所选模型”：这会发送最多 64 输出 token 的简短请求，可能使用相应额度。认证或调用失败会显示错误，已保存的 Key 不会因此丢失。

Key 与设备授权刷新令牌在后端加密保存，不进入普通基座字段、外观导出或工具返回值。移除账号后，其关联调用明确失败，不自动改用其他 Key。旧单 Key 配置和旧模型引用保持 `default` 账号绑定。

## 模型选择与计费目录

模型来自官方 Go / Zen 目录，缓存五分钟并支持刷新。Zen 目录包括免费与按量模型；具体计费、限流和账号权限以官方服务为准，不凭模型名称猜测价格。公开目录和协议适配状态不能证明账号具有对应套餐权限。

Go 与 Zen 使用不同请求路径。选择的目录固定到会话，不因请求失败自动改用另一计费路径。官方账号已开启的超额余额设置由官方服务决定，扩展不修改该设置。

已适配 Chat Completions、Responses、Anthropic Messages 与 Gemini 文本和工具调用。未知协议模型可以显示为待适配，不能作为已可调用模型。模型菜单包含已适配的目录模型；最终是否可用由认证与实际调用结果决定。

会话创建时保存完整账号、目录和模型引用。子任务继承该选择；修改基座默认模型不会改变已有会话。旧会话载入时固定其已有基座模型。更换模型可创建新会话。

## 官方用量

Go 用量通过 `GET /inference/go/v1/usage` 查询，解析 `usage.rolling`、`usage.weekly`、`usage.monthly` 内的 `percent` 和 `resetsAt`，并兼容旧的 `rollingUsage` / `weeklyUsage` / `monthlyUsage` 格式。

页面显示 5 小时、每周、每月使用百分比及重置时间。零用量是有效值。缺字段、鉴权失败或接口变化时说明不可查询，不把本地估算伪装成官方额度。这些百分比不是现金余额，当前不提供现金余额 API。

## 流式响应与会话

扩展保留各供应商流式输出，逐段转换为统一消息契约，不等待整个响应结束后再显示。截断流不会被标记为正常完成，工具参数与 Gemini thought signature 按协议保留。主智能体请求使用扩展 User-Agent 和稳定的 `x-opencode-session`。

停用扩展后后端拒绝新调用，账号与基座配置保留；重新启用后可继续使用。设备令牌串行刷新，刷新前保存状态；网络异常或重启导致轮换结果未知时要求重新登录，不盲目重放单次刷新令牌。

## 验证范围

- `tests/opencode.test.ts`：15 项测试覆盖多账号、账号单基座、认证与推理分离、Go / Zen 路径、额度结构、会话模型持久化和继承、停用、凭据隔离、令牌轮换及流式首段/截断。
- `scripts/opencode-ui-smoke.ts`：账号接入、保存检测、额度与窄窗口交互。
- `scripts/opencode-pane-smoke.ts`：400 / 550 / 700px 实际扩展与智能体容器，检查溢出和工具行重叠。
- 2026-10-20 已核对用户账号返回的官方 Go 用量结构，用于修正解析。未用该 Key 逐模型发起线上推理验收；真实设备授权、不同套餐/限流和新增模型兼容性仍需实际使用验证。
