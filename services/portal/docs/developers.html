从一个命令，到一份独立进程扩展。选择运行位置，声明工具契约，让同一项能力进入命令台、智能体与 MCP。

先跑通一份独立扩展

仓库提供只把文本转换为大写的最小示例，不访问连接或用户文件。在源码根目录构建：

node examples/process-extension/package.mjs
  1. 将生成的 example.echo.cshellext 导入 CShell，核对来源和权限。
  2. 从“自定义扩展”启用，再单独“授权运行”。导入、启用与授权彼此独立。
  3. 在命令台通过 tools 找到真实工具名，用 help 工具名 查看参数，再调用。智能体和 MCP 使用同一契约与权限检查。

工具在哪里运行？

安装到 CShell

运行在控制端电脑。切换机器标签不会改变扩展的运行位置。

安装到目标 CAgent

在目标机器独立导入、重启并授权，通过该机器能力目录调用。账号同步不会复制可执行包或运行授权。

进程扩展有超时、输出和并发限制，仍具有宿主系统用户的权限；进程隔离不是操作系统权限沙箱。应用安装、版本检查和能力授权分别验证，安装完成不等于工具已可用。

源码贡献流程

  1. Fork 源码仓库，阅读仓库 AGENTS.md 与相关协议。
  2. 在独立分支实现，复用现有设计组件、Provider 与授权边界。
  3. 为实际行为补充验证：目标绑定、断开、撤权、取消与失败。
  4. 提交 PR，写明功能入口、支持系统、权限、副作用和测试结果。
  5. 审核合入并随版本发布后，才能把新的可信 Provider 标记为可用。

不要把密钥放在渲染进程、清单或示例中；不得用静态演示数据冒充机器实时能力。
