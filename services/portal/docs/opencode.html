OpenCode 账号与模型

添加一次账号，直接选择模型

  1. 在扩展中启用 OpenCode，保存账号 Key 或完成浏览器登录。
  2. 打开智能体输入区的「AI 基座与模型」，进入 OpenCode 分类。
  3. 在账号的二级菜单中搜索、选择 Go 或 Zen 模型，开始新会话。

不必把每个模型逐一填入基座。Key 只在账号设置中填写，不放入普通对话；已运行的会话继续使用原模型，切换模型不会改变它正在执行的任务。

列表什么时候更新

打开模型菜单、应用回到前台，以及云端恢复账号后，会重新获取目录。可手动刷新，但无需每次重新接入账号。模型排序变化不会更换默认值；目录暂时无法读取时显示状态未知，保留账号和历史。

Go 和 Zen 分开显示。没有明确选择模型时不发起推理；不会为了恢复可用状态自动选择付费模型。扩展页的账号验证也不会更改默认模型。

旧模型失效时会发生什么

基座设置、模型菜单和实际调用共用可用状态。已下架、协议未适配、服务端拒绝、目录加载失败分别显示原因；失效模型不作为新会话的回退选项。原账号、密钥、模型引用和会话历史保留。

账号认证、模型目录与实际生成是三个状态。认证成功不等于每个模型都能调用。调整套餐或网络出口后，可在扩展页明确选择模型并点击「检测所选模型」；检测成功后恢复该模型状态。检测会发送实际请求，可能使用对应模型额度。

桌面端使用官方 OpenCode 运行时

首次发送或检测时，CShell 按系统准备官方 OpenCode 1.19.4 私有运行时，下载并校验摘要后再启动。支持 Windows x64、macOS x64 / arm64、Linux x64 / arm64；Android 不启动桌面可执行文件。首次下载较大，失败时可重试，原账号不会被删除。

运行时保存在 CShell 的专用数据目录，不改全局 PATH，也不接管已有 OpenCode 配置。模型请求沿用「设置 → 网络代理」中的出口；指定机器不可用时失败，不回退本机直连。停止会话会清理该请求的进程，其他会话继续运行。

智能体工具仍由 CShell 按原有权限与审核执行。官方运行时不能自行访问本机文件或执行 Shell；它返回工具意图后，由 CShell 核验目标、参数与授权。进程隔离不等于系统权限沙箱，运行时程序仍以当前用户运行。开发细节见运行时与工具边界。

403 或免费层拒绝，怎么处理

地区、套餐、额度或客户端范围限制均由服务端判断，不一定是 Key 错误。先看错误原因与所选 Go / Zen 模型，避免反复删除账号。网站的验证码、多因素认证和其他正常验证步骤仍需完成。

2026-10-25 实测：现有账号通过真实官方运行时调用 beam-free、mimo-v2.6-flash-free 和 big-pickle 均返回 403；未修改的官方 OpenCode 命令行也出现免费层拒绝。因此，官方运行时接入已经实现，但不能承诺这些免费模型当前可用。没有伪造客户端标识，也没有自动改用付费模型。

可以选择服务商明确允许当前账号使用的模型，或在调整合规网络出口后明确重新检测。若服务端继续拒绝，保留错误代码并向服务商核实；CShell 不会自动绕过限制。

反馈问题需要哪些信息

提供 CShell 版本、开源 / Pro、模型 ID、错误代码、发生时间、网络出口类型，并说明是目录加载失败还是实际生成失败。不要提供 Key、Authorization、Cookie、密码或完整连接凭据。
