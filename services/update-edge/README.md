# Emergency update download edge

Temporary fallback for the unavailable Hong Kong origin. The generated module embeds only publicly published Yeqi99/CShell v0.8.16 and pro-v0.8.16 metadata. It needs no token or secret binding. No deployment is performed by these scripts. The emergency Worker is now deployed with the four routes below; production acceptance is recorded in ACCEPTANCE.md and production-acceptance.json.

Deploy `deployment.json` code as an ES module Worker with its compatibility date, then register only the four entries in `routes`: the two exact releases.json URLs and the two v0.8.16 asset subtrees. Do not route all /downloads/*: installer scripts, future releases and other site resources must remain untouched. Future release publication must update this pinned manifest or remove the emergency routes, otherwise release checks stay on 0.8.16. Rollback is deleting these four route bindings; do not change origin DNS or other routes.

`node generate.mjs` queries the public GitHub API, rejects drafts, prereleases, unexpected tags/counts/URLs or missing SHA256 digest and writes the 30-asset allowlist plus deployment bundle. Catalogs retain the existing v0.8.16 tag and edition-specific mirror URLs. This emergency catalog includes only the current stable release, not historical downloads.

`node --test worker.test.mjs` covers exact allowlisting, bad methods, credential stripping, hostile redirects, HEAD, single byte ranges, length/content-range verification. `node check-live.mjs` downloads both complete SHA256SUMS files through the same Worker handler, verifies their SHA256 against the API and every listed package hash against the allowlist; also retrieves 1024 actual bytes of each edition's CAgent installer with status 206. No client redirect is returned. HEAD responds from pinned metadata (X-CShell-Verification: pinned-metadata-only); it does not prove upstream liveness.

GET streams the original payload without buffering the installer. Initial headers have a bounded timeout, but the timeout is cleared before the potentially long body transfer. Upstream redirects are followed internally only from a pinned GitHub release URL to HTTPS release-assets.githubusercontent.com; caller cookies, authorization and arbitrary query destinations are never forwarded. Unknown paths fail 404 and upstream mismatch fails 502. Single Range requests support resume; malformed or multipart ranges fail 416. Client-side SHA256 verification remains required: streaming checks status and length, not the entire installer digest. The live test validates the small checksums files fully, not every full installer in this run.
